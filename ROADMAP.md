# lexicon — roadmap

*A working list, not a finished plan. Elements/ has stopped being the bottleneck — what's left is plumbing, breadth, and surface. Items below are what gets pulled next, organized by what they're for, not when they were thought of.*

## Operating principle

Elements/ is a vocabulary, not a destination. Atom-count is no longer the binding constraint on usefulness — composition, surface, and the tools downstream from elements/ are. The default move is to use what's already built and notice what it lacks; the secondary move is to add. The tertiary move is to invent. Most leverage lives in moves one and two.

## Polish and public surface

The project was held private until it could be flipped without cringing. Both named gates are now done as of 2026-08-20: the quote-fidelity audit (825 flagged spans across three buckets read by hand, zero fabrications; a real classification bug in the checker itself — flat quote-mark parity conflating depth-0 with depth-2 nesting — found and fixed) and the top-level prose pass (SCHEMA's source/tradition enum conflict and insider narration fixed; a dedicated release-scrutiny sweep beyond just SCHEMA — private paths, AI-conversation-trace phrasing, a `quote:` field with editorial narration welded past its closing mark, a hardcoded sibling-repo path in `lexicon want` — found and fixed). The periodic-table classification structure and the ID renumbering it unlocked (see *Elements maintenance*) were already done. **Flipping the repo public and/or enabling Pages is still a separate, deliberate, unactioned step** — nothing here does it automatically. Two smaller items surfaced by the sweep are open judgment calls, not blockers: a handful of Go source comments cite sibling repos (`cupel`, `sluice`, `hindcast`) by name without a link, and two atoms (`lex-tqa55`, `lex-cbrcm`) cite this project's own private hook log as evidence, which a stranger can't verify.

- **Public demo on GitHub Pages — live.** Re-enabled 2026-08-21 after the release-scrutiny sweep above. `.github/workflows/pages.yml` builds the `web/` React SPA (see *Surfacing*'s viz-rebuild entry) as the landing page, with the legacy matrix/pivot/shell views kept at stable URLs, and serves from `https://justinstimatze.github.io/lexicon/`. A Pages site built from a private repo is still publicly reachable at its github.io URL — repo visibility and Pages visibility are separate switches; check `gh api repos/justinstimatze/lexicon/pages` for the Pages state specifically rather than inferring it from the repo's own visibility. No hosted paste-in endpoint is planned; strangers who want the surfacing function can clone and run `lexicon read`.
- **Top-level prose pass — done (2026-08-20).** README and ROADMAP were already in shape; SCHEMA's drift is fixed, and the broader release-scrutiny sweep (private paths, AI-conversation traces, TODO markers, personal handles, forge metadata, a stranger's-eye reread of the top-level docs) found and fixed real issues beyond SCHEMA — see the paragraph above.
- **Cross-citation linter** (see *Elements maintenance* below). The class of failure where atom A's prose names atom B by name, and B gets renamed silently — this is the next gate to add. Cheap, additive, doesn't change the data model.

## Elements breadth

Elements/ coverage is dense where it started (reasoning, argument schemes, defeasible inference, power dynamics, philosophy-of-mind) and thin where it hasn't traveled. The breadth-side roadmap is the latter set.

- **Anthropology and Brown's Human Universals.** Kinship, gossip, gesture, dance, magic, naming, property, hospitality, oath, gift, ritual — most have zero atoms by name. The HRAF tradition and Brown 1991 *Human Universals* are the entry points.
- **Emotional primitives beyond reasoning-emotions.** Grief, pride, disgust, contempt, embarrassment, loneliness, boredom — elements/ has envy (a recent molecule pass) but the rest is thin. Ekman + Frijda + Scheler + Nussbaum are the entry points.
- **Embodiment and craft.** Body-knowledge, somatic primitives, apprenticeship, tacit skill, taste-by-doing. Polanyi *Personal Knowledge*, Sennett *The Craftsman*, Dreyfus on skill acquisition are the entry points.
- **Non-Western traditions beyond what's mined.** Elements/ has Madhyamaka primitives and some Daoist + Vedic mining; the gap is African and Indigenous philosophy traditions where pattern-libraries exist.
- **Modern professional fields' canonical pattern-libraries.** Architecture (Alexander already done), biology, ecology, software engineering, organization design — each field has a canonical pattern-language; the mining is the remaining work.

## Tooling

The CLI and MCP surface are mostly built. The next moves are polish, agent-first defaults, and the operational primitives surfaced by use.

- **Agent-tool-first refactor.** JSON-default output everywhere; current markdown-default surfaces on `lexicon read` and `lexicon list` flip. Most consumers are LLMs; JSON makes composition trivial and structured grep cheap.
- **`lexicon read --partitions`.** Cross-domain firing aggregator: take N passages (one per domain), return atoms that fired across ≥K partitions. Surfaces slow-variables and scale-separated patterns at the elements level. Composes with `lexicon extrapolate` (already shipped) for forecasting-back-test pipelines.
- **Elements-graph navigation.** `lexicon find` and `lexicon backrefs` are partly shipped; what's missing is rich elements exploration from the agent surface — sibling lookup, cluster expansion, status filtering, weighted-distance queries.
- **Reaction-tier maturity.** Reactions are first-class in the schema; the surrounding tools (catalysts and inhibitors visualization, intervention-planning from constellation → product) need more polish.
- **Optimal-utility research: what makes lexicon maximally useful to Claude Code specifically, as opposed to LLM agents generally.** The agent-tool-first refactor above is about output format (JSON over markdown); this is a different question — given Claude Code's actual usage shape (hooks, skills, context-injection points, session lifecycle, subagent fan-out), where does a passive-injection surfacing tool like lexicon's actually earn its keep, and what's the highest-leverage integration point? A prior design pass already leaned toward passive context-injection (a hook surfacing relevant atoms unprompted) over an RPC-style tool a model has to remember to call — deep-reasoning models in particular tend to forget about external tools mid-chain unless the surfacing is ambient. This item is the research pass that turns that direction into a concrete integration design.

## Elements maintenance

The current gate stack (`lint`, `lint-cross-refs`, `db lint`, reciprocation) catches the common failure modes. **The pivot-table classification structure was the release gate** (see *Polish and public surface*) — not the "if the pain forces it" framing this section was originally written under. The classification axes are real, not speculative, and the release-gate content pass is done: the pivot UI is built, the mechanism-family axis it feeds is computed live from the graph (see *Surfacing*), and all 31 previously-empty grid cells are triaged with candidates.

**ID renumbering — done (2026-08-20).** All 1,088 `lex-NNNN` sequential ids replaced with non-sequential 5-character opaque codes (e.g. `lex-NNNNN` shape, alphabet `23456789abcdefghjkmnpqrstuvwxyz`) so identity no longer carries the appearance of mining-ingestion order. Built as a one-off `lexicon renumber` subcommand (`plan`/`apply-rename`/`apply-content`/`next-id`): draws a collision-checked mapping, sweeps every tracked file plus the gitignored working queues (`wanted-materials.md`, `mining-queue.md`, `acquired-materials.md`, `.session-handoffs/*.md`) via `git ls-files`, renames all 1,088 elements files, and rewrites every `id`/`related`/`evokes`/`decomposes-into`/prose-citation occurrence. The permanent old→new mapping lives at `docs/id-migration-map.csv`, kept forever since prior session notes and commit messages cite old ids. Landed as a single commit (the planned rename-then-content two-commit split proved infeasible — the pre-commit hook's `lint` step requires elements/ to be loadable, i.e. filename and internal `id:` agreeing, at every commit boundary). Caught a real word-boundary regex bug along the way: the new alphabet spans most of a-z, so several un-anchored `lex-` prefix regexes in the lint tooling started false-matching mid-word inside ordinary compound words like "complex-systems"; fixed with `\b` anchors. Verified: `lint`/`lint-cross-refs`/`db lint` all at the exact pre-migration baseline, 12,746 edges unchanged, `go build`/`go test` clean, live browser check of the rendered pivot UI clean.

**DB migration — done, scoped down (2026-08-19).** The felt pain behind "database migration" was the two-file (YAML + `docs/passes/*.md` mirror) hand-reciprocation tax `check-drift` enforced. Research found the mirror never functioned as real shared state — it's gitignored, per-machine, and had already orphaned atoms minted on a different machine after a merge. The fix: retire the mirror and `check-drift` (deleted, along with `internal/driftcheck`), make `render/internal/db/`'s SQLite index schema-complete (it now captures every `types.LexEntry` field, including `scaffolds-from` and `encounter-tier-override`), swap `check-drift` for `db build` + `db lint` in the pre-commit hook, and simplify `patch-related` to a single-file YAML patch (it also now reads block-list `related:` form, not just inline). `elements/*.yaml` stays the sole hand-edited source of truth — no CRUD-edit CLI was built, and none was needed.

The bigger version of this — the DB becoming canonical, YAML becoming a generated export, a real edit CLI replacing hand-editing YAML — stays a named, larger, unstarted option below. It turned out not to be required for anything currently queued.

- **Cross-citation linter.** Extract `lex-NNNN` mentions from atom prose fields; verify the adjacent text matches the referenced atom's current name. The gap that recent mining made concrete: when atom A names atom B by name in canonical-instances or lineage, no gate catches it if B gets renamed. Cheap, additive. *(Partial: `related-unresolved` is now ERROR severity; the prose-side name-drift catcher already exists as warning-tier `stale-cross-citation`.)*
- **Template-macro substitution at render time.** The current dual-key citation pattern in prose — `lex-NNNN <dashed-name>` — duplicates the truth between an immutable ID and a mutable name. Every rename creates a sync burden caught by the warning-tier lint. The principled fix: a render-time macro like `{{ref lex-mthv9}}` that substitutes the current canonical name at build/serve time. Eliminates name-drift as a class. Larger refactor — touches the YAML schema (the prose fields), the renderer (read pipeline), the agent-tools API. Deferred until the citation-rewrite pain forces it.
- **Eventual full DB-canonical migration.** Move the elements/ source-of-truth off YAML entirely onto the DB, with YAML generated as an export and a CRUD-edit CLI replacing hand-editing. Heavy move — needs a schema-migration + rollback story and a decision on what (if anything) still gets hand-edited as text. Only justified if the maintenance pain of hand-editing YAML itself (not the now-retired MD-mirror tax) starts to bite.

## Surfacing

The surfacing function works — `lexicon read` returns named-pattern decomposition with adjacencies and explanations. The remaining surfacing work is at the edges.

- **Viz layer rebuilt as a React SPA — DONE (2026-08-20).** A survey ahead of this work found the three sub-items here weren't "unbuilt" — `render/internal/viz/` held four independently-evolved rendering stacks (a cytoscape.js force graph, a hand-rolled Canvas2D matrix, an HTML-table pivot, and a hidden `lexicon holo` 3D view already using `3d-force-graph`/Three.js, absent from `--help`), 4,450 lines of Go string-literal HTML with no shared component architecture — the exact trap `frontend-stack`-style guidance warns against, now visible at scale. Rebuilt `web/` (Vite + React + Tailwind + shadcn/ui) consuming the same `viz.Graph` data contract (`lexicon export-graph`) every Go renderer already used, and it's now the GitHub Pages landing page (`scripts/build-web.sh`, still `workflow_dispatch`-only — see *Public demo* above):
  - **Multi-scale zoom UI**, done as zoom-driven LOD on the 3D graph rather than a separate view: past ~1.35× the camera's fit distance individual atoms dim into a 9-label `type_in` category cloud (the coarsest grouping the data actually carries); inside ~0.45× the nearest atoms grow billboarded name labels. An idle-orbit → screensaver-tour ladder (ported from `holo.go`) swoops between hub atoms and cycles layout lenses when left alone.
  - **3D / n-D visualization**, same component: 4 precomputed layout lenses (cosmic-web, cluster-puffs, degree-shells, type-grid), runtime physics disabled, verified via direct Three.js scene inspection rather than screenshots alone (a throttled label-refresh bug that left the atom-detail labels silently empty was caught this way, not by eye).
  - **Pivot-table gap-finding UI**, ported to `web/src/components/PivotTable.tsx` with the same 31 real gap cells (of 90) and their candidate hypotheses — `gapSuggestions` from `shell.go` sliced mechanically into `web/src/lib/gapSuggestions.ts` rather than retyped, since it's citation-bearing prose (Loewenstein, Foucault, Chomsky, Hennig, and more). The Go-rendered original (`render/internal/viz/pivot.go` + `shell.go`, built and triaged 2026-08-20 before this rebuild) stays reachable at `pivot.html` and `shell.html` as legacy URLs; its content is what got ported, not redone.
  - Retired: `lexicon viz` (cytoscape, zero mobile support to lose) and `lexicon holo` (superseded by the React port) are gone from the CLI; `render/internal/viz/html.go` and `holo.go` are deleted. `lexicon matrix` (Canvas2D adjacency matrix) has no React equivalent yet and stays, reachable directly or composed with pivot + a shared detail pane via `lexicon shell` — now a secondary legacy view, not the landing page.
  - **List view added (2026-08-20)** — a third lens, `web/src/components/ListView.tsx`: a sortable, filterable flat index of all atoms, the one view where the catalog reads top-to-bottom rather than spatially or by type-shape. Same data contract, no new dependency; `AtomCard` (atom detail rendering) extracted out of `PivotTable.tsx` so both views share it. A cold-read pass on the SPA the same day also fixed dead chrome (fake window-decoration dots), a header nav that looked clickable but wasn't, an unthemed default scrollbar, and switched the 3D graph's default lens from `cosmic-web` (one dense blob plus outliers) to `cluster-puffs` (the same data, legibly separated). A follow-on idea from the same conversation — composing multiple layout paradigms at different scales in one 3D view (grid/lattice sub-layouts per cluster, placed by the existing macro force step) — has real prior art (NodeTrix, hierarchical edge bundling, hive plots) but is a new Go-side layout, not scoped or started.
- **Anki-deck export — DONE, redesigned 2026-08-21.** `lexicon anki` existed already but shipped one card per atom cramming agent-instruction, citation, an example, and related[] together — exactly the wall-of-text anti-pattern spaced-repetition design guidance warns against (Wozniak's minimum-information principle: one card tests one fact). Redesigned to two cards per atom instead: a recognition card (scenario on the front, pattern name on the back — comparison-heavy canonical-instances like "operationally distinct from lex-NNNN..." are skipped as fronts, since they presuppose the very recognition being tested) and a recall card (name + type signature on the front, the single agent-instruction plus a short source attribution on the back). Also fixed markdown-style `*italic*` citation titles rendering as literal asterisks in Anki's HTML view. Wired into `scripts/build-web.sh` as `public/lexicon-anki.tsv`, linked from the README.
- **Cluster pass on the `related[]` graph — DONE (2026-08-19).** Louvain community detection (networkx, run against the `atom_related` SQLite table) over 6,324 undirected edges (12,648 directed, fully reciprocated) across 1,088 atoms. Modularity 0.4658 — real community structure, not soup. 13 substantial communities (9–124 atoms, 1,058 atoms covered) read as coherent themes on inspection: virtue-ethics/phronesis, Walton's defeasible-argumentation schemes, feminist/critical-theory power analysis, Daoist non-coercive-action, the Prahalad-Hamel competitive-strategy cluster isolating cleanly on its own. Side finding: 22 atoms (`lex-663sq` and later — the most recent mining passes) had zero `related[]` edges and sat outside every cluster. Read-only probe — extracted the existing graph, ran community detection, wrote nothing back to elements/.
- **22-atom linking gap — closed (2026-08-20).** Each isolate read by content and linked to 2–5 genuinely related atoms — sibling atoms within the same mining pass (the four Johnstone status/improv atoms, the Goffman face-work pair, the humor-theory trio, the McNeill muscular-bonding pair, the three linguistics-foundations atoms) plus existing atoms on the same claim (Kleinman's reliability-vs-validity paired with his own category-fallacy atom; Hohwy's attention/precision chapter paired with his delusion/precision chapter; the Berlin & Kay and Westermarck atoms paired with their near-duplicate existing counterparts). 49 reciprocated edges added via `patch-related`, touching 50 atoms total (22 isolates + 28 existing). `db query`'s isolate check now returns zero rows; `lint`/`lint-cross-refs`/`db lint` all still at 0 errors post-patch (12,746 edges, up from 12,648).
- **Molecule-tier under-development, though far less than it was.** The full compose-with sweep (44 atoms whose own prose already said "Composes with lex-NNNN") is closed out: the self-deception cluster split into lex-gq42q (molecule) + lex-hndyu (reaction, not molecule — its constituents' types don't chain), the 18 small/clean clusters yielded 15 molecules (lex-swxmz–lex-z6u9z), and the 3 large dense webs (21/11/10 atoms) — each mostly two-or-more distinct traditions bridged by a few cross-cites rather than one big mechanism — yielded 8 more (lex-qy2ej–lex-xwbjd). Molecule mining is the higher-leverage structural work once atomic mining settles — it's what makes composition-level structure observable. Next: this specific sweep is done; a fresh discovery pass (new co-occurrence signal, or a new mining wave's own "Composes with" self-citations) is what surfaces the next candidate set.

## Deferred and explicitly not on the table

A few directions get deferred for narrower reasons:

- Building new failure-pattern detectors. Lexicon sits below the detector layer as the vocabulary detectors speak — that work belongs in dedicated detector tools, not here.
- Original cognitive science. Elements/ consolidates existing rigorously-curated catalogs plus a small handful of practitioner-surfaced primitives. The contribution is the format and the surfacing function, not new primitive content.

*The catalog grows, the surface tightens, the breadth widens. None of these items are committed in date order — they're pulled when their leverage rises above the work they displace.*
